本文档记录的是**测试的规划与原则**，不代表任何测试已经编写或通过。

## 规划中的测试分层

| 层级 | 测什么 | 候选工具 | 建议引入阶段 |
| --- | --- | --- | --- |
| 单元测试 | 字段归一化、日期与金额解析、证据完整性规则、「用户陈述 / 材料识别 / AI 推断」三类来源标记 | Vitest | 阶段 4（字段核对逻辑成型后） |
| 检索测试 | 中文分词、短关键词、典型查询在 SQLite FTS5 下的命中率与排序质量 | Vitest + 固定查询集 | 阶段 6（法规检索实现后） |
| 端到端 | 上传凭证 → 字段核对 → 时间线 → 分析材料 的完整闭环 | Playwright | 阶段 9（界面稳定后） |
| 人工验收 | 结论是否符合「不编造法规」「标注不确定」等产品红线 | 人工 + 检查表 | 每阶段末 |

引入原则：**按实际测试需求分阶段引入，只为已被证明需要测试的行为写测试**，
不提前搭建空脚手架。

## 测试证据的保存

- 测试命令与真实输出属于 AI 协作证据的一部分，记录在
  `prompts/<分类>/<记录ID>.md` 的「实际执行的检查」小节。
- 测试报告截图（脱敏后）可放入 `evidence/screenshots/`，但注意该目录默认
  忽略图片格式，需要提交时按 `evidence/README.md` 的规则显式白名单。
- 不得在 README 或其他文档中写入未实际运行过的测试结果。
