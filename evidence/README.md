# evidence —— 项目证据库

本目录存放「可核验的项目证据」的**索引与规范**。
原始素材体积大且可能含隐私，**默认不入库**；仓库里只保留脱敏索引、规范和必要的占位文件。

## 目录分工

| 目录 | 存什么 | 是否提交 | 说明 |
| --- | --- | --- | --- |
| `ai-collaboration/` | **核心功能的 AI 协作证据索引**：把 Prompt 路径、Git 提交、截图、录屏、测试记录串联起来 | ✅ 提交（纯文本索引） | 唯一「索引主副本」所在处 |
| `screenshots/` | 界面/终端截图（含原始截图与脱敏后的最终截图） | ⚠️ 默认不提交（图片格式已忽略） | 需要提交时按下方规则加白名单 |
| `recordings/` | 面向 AI 协作证据的原始录屏（工具录制的分段素材） | ❌ 不提交 | 本地保存 + 备份 |
| `demo/` | 最终剪辑的 Demo 成片（1080P MP4）及字幕、分镜脚本 | 成片 ❌ 不提交；脚本/分镜文本 ✅ 提交 | 提交到比赛平台或提供网盘链接 |

## 三层材料必须区分清楚

同一份内容只保留一个**主副本**，其他位置一律用相对路径引用，不复制正文。
材料按性质分为三类，任何文件都必须能被判断属于哪一类：

| 类型 | 定义 | 命名与标注要求 |
| --- | --- | --- |
| **原始导出（raw）** | 工具真实导出的完整记录，未经编辑 | 文件或目录名含 `raw` 或 `原始`，已被 `.gitignore` 忽略，不进仓库 |
| **脱敏副本（redacted）** | 由原始导出编辑而来，删改了隐私/密钥片段 | 文件名含 `-redacted`，文首必须写「脱敏范围」清单 + 原始文件相对路径 |
| **人工摘要（summary）** | 人写的索引、结论、评审意见 | 文件名含 `-summary` 或以索引形式存在，必须写作者与时间，且不得冒充原始记录 |

**脱敏副本不得冒充原始记录。** 如果只在摘要里存在某句话，就不能把它当作「AI 原话」引用。

## 提交规则（重要）

1. **永不提交**：真实消费凭证、身份证/银行卡照片、含手机号或地址的界面截图、
   含 API Key 的终端截图、原始录屏、原始对话导出 JSON/HTML。
2. **可提交**：纯文本的索引、规范、检查表、测试命令与输出（脱敏后）、
   已明确标注的合成数据文件。
3. 图片与视频格式在 `.gitignore` 中通配忽略。确需提交某一张脱敏截图时，
   在 `.gitignore` 末尾新增精确白名单（例如 `!/evidence/screenshots/03-01-fields-redacted.png`），
   并在提交前用图片查看器逐张确认无隐私，再在
   [比赛材料清单](../docs/比赛材料清单.md) 中登记。
4. 大体积素材（录屏、成片）在本地保存并做**离线备份**，
   备份位置与时间记录在 `evidence/recordings/README.md`、`evidence/demo/README.md`。
5. 单个文件超过约 50 MB 时不要进 Git；如需版本管理媒体，另行评估 Git LFS
   （当前未安装配置 LFS 钩子，仅探测到 `git-lfs` 命令存在）。

## 命名约定

```
<阶段>-<主题>-<序号>-<类型>.<扩展名>
例：s01-init-01-terminal-env.txt
    s03-ocr-02-ai-diff-redacted.png
    s07-demo-01-script.md
```

阶段前缀沿用开发路线图的阶段号（见 [项目开发路线图](../docs/项目开发路线图.md)）。
