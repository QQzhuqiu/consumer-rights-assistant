## 2. 首发场景（✅ 已确认：场景 A）

选择标准：**凭证可得、法规明确、纠纷金额小但争议点典型、闭环能在 10 分钟演示内完成**。

### 已选定：电商商品「七天无理由退货」被拒

| 项 | 内容 |
| --- | --- |
| 用户处境 | 网购商品收货后 7 日内申请无理由退货，商家以「已拆封/影响二次销售」为由拒绝 |
| 输入凭证 | 订单页截图、商品详情页截图（是否标注「7 天无理由」）、与商家的聊天记录、物流签收记录 |
| 争议焦点 | 拆封是否属于「影响二次销售」的例外；商家页面的格式条款是否有效 |
| 为什么合适 | 规则有明确法定依据；凭证均为手机截图、易获取；闭环短，适合 10 分钟演示 |
| 产品边界（本场景） | 只整理事实、列出可核验条文、生成沟通草稿；**不判断最终能否退货成功、不代发投诉** |
| 法规线索（**均待核实原文后引用**） | 《消费者权益保护法》关于七天无理由退货及不适用情形的条款、《网络购买商品七日无理由退货暂行办法》相关条款——**具体条号、原文、生效状态在阶段 7 前必须到官方发布页核对，不得凭记忆写入产品** |

### 未采用的候选（留档，备后续扩展）

| 候选场景 | 未采用原因 |
| --- | --- |
| B. 货不对板 / 虚假宣传退赔 | 涉及举证责任分配，AI 结论边界更难收紧 |
| C. 预付卡 / 会员卡不退费 | 合同条款识别难度高 |
| D. 快递破损或丢件理赔 | 赔付主体判断复杂，闭环较长 |

无论哪个场景，产品范围内**不做**：代为投诉、代替用户签署文件、给出确定性法律结论。

## 5. 不做的范围（防止范围膨胀）

- 不做多场景并发开发，先跑通一个场景。
- 不做用户账号体系、支付、社交等非核心功能（除非评审明确要求）。
- 不做 Embedding 优先方案，优先验证 FTS5（见技术方案评估）。
- 不做多模型调度框架，先做最小适配层。
- 不做「自动帮你投诉/起诉」类功能。
