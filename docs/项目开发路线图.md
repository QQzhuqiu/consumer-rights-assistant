# 项目开发路线图

> 原则：**先做一个范围受控的消费纠纷场景，跑通完整闭环**，再扩展场景宽度。
> 本文件中的一切都只是**计划**，未完成的阶段不标记为已完成。
> 比赛截止时间未核实，因此不生成依赖具体日期的倒排承诺；阶段用「前置条件」而非「X 月 X 日」约束。

## 2. 首发场景（候选，待用户确认）

选择标准：**凭证可得、法规明确、纠纷金额小但争议点典型、闭环能在 10 分钟演示内完成**。

| 候选场景 | 为什么可能合适 | 待确认点 |
| --- | --- | --- |
| A. 电商商品「七天无理由退货」被拒 | 规则明确（消费者权益保护法相关条款），凭证为订单页与聊天记录 | 平台规则与法定规则的冲突点如何处理 |
| B. 网购商品「货不对板 / 虚假宣传」要求退赔 | 凭证充分，用户痛点强 | 涉及举证责任，AI 结论边界要收紧 |
| C. 预付卡 / 会员卡不退费 | 典型高频 | 合同条款识别难度高 |
| D. 快递破损或丢件理赔 | 凭证结构化 | 赔付主体（快递公司/商家）判断复杂 |

**建议先选 A**（规则清晰、闭环短、法规依据明确），最终由用户确认。
无论选哪个，产品范围内**不做**：代为投诉、代替用户签署文件、给出确定性法律结论。

## 3. 各阶段详情

### 阶段 1 · 场景确认与产品边界

| 项 | 内容 |
| --- | --- |
| 目标 | 把首发场景写清楚，明确输入、输出、不可做的事 |
| 前置条件 | 用户确认场景 A/B/C/D 之一 |
| 最小交付物 | `docs/场景说明.md`（用户旅程、输入输出示例——**使用合成样例**）、边界与免责声明文案 |
| 验收条件 | 能逐条回答「输入是什么/输出包含哪几章节/哪些事坚决不做/如何去标识不确定」；用户书面确认场景 |
| 证据位置 | `prompts/01-项目初始化/` 或新建分类记录；`evidence/ai-collaboration/00-初始化阶段.md` |

### 阶段 2 · API 小规模测试

| 项 | 内容 |
| --- | --- |
| 目标 | 用**最小调用次数**验证一个文本模型、一个图片模型的实际能力、真实模型 ID、响应结构、费用 |
| 前置条件 | ① 用户提供服务商与中转地址；② 用户确认**单轮费用上限**；③ 密钥写入本地 `.env.local`；④ 明确本次测试总调用次数上限（建议 ≤ 10 次） |
| 最小交付物 | `docs/API测试报告.md`：真实模型 ID、单次请求/响应结构、图片能力结论、超时与错误码、token 与费用实测、失败项 |
| 验收条件 | 报告中的每个数字都有对应日志（脱敏）；**未验证项明确列出**；总支出 ≤ 用户设定上限 |
| 证据位置 | `prompts/02-核心功能开发/`；终端记录（脱敏截图，可选）；`.env.example` 字段按结论更新 |
| 风险 | 中转服务可能不返回标准用量字段；图片能力可能不支持 → 需准备「无图片能力」的降级方案（用户手填字段） |

> **在用户确认之前不发起任何 API 调用。**

### 阶段 3 · 基础界面与项目骨架

| 项 | 内容 |
| --- | --- |
| 目标 | 建立可运行骨架（App Router + TypeScript + Tailwind），跑通一个空壳页面 |
| 前置条件 | 阶段 2 结束（至少确认模型可用性，避免架构反复） |
| 最小交付物 | `package.json`、`app/layout.tsx`、`app/page.tsx`、`tailwind` 配置、`npm run dev` 可启动 |
| 验收条件 | 本地启动成功并截图（脱敏）；`npm run build` 通过；README 增加启动说明（此时才可写可执行命令） |
| 证据位置 | Git 提交 + `evidence/screenshots/`（脱敏）+ Prompt 记录 |
| 注意 | 届时需重排 `src/` 结构（`create-next-app` 可用 `--no-src-dir` 或用 `src/app`），并同步更新 `src/README.md` |

### 阶段 4 · 凭证上传

| 项 | 内容 |
| --- | --- |
| 目标 | 支持上传图片（限类型与大小），临时落盘，提供删除入口 |
| 前置条件 | 阶段 3 完成 |
| 最小交付物 | 上传页面、服务端接收、文件类型/大小校验、删除接口 |
| 验收条件 | 拒绝非图片与超大文件；上传后可在本地 `data/uploads/` 看到且**不被 Git 跟踪**（`git status` 干净）；删除后文件确实消失 |
| 证据位置 | `evidence/ai-collaboration/01-...` 索引（首个核心功能起点）；`evidence/recordings/` 录屏 |
| 隐私 | 文件名随机化、不保留原始文件名中的个人信息 |

### 阶段 5 · 图片信息提取（**核心功能 ①：凭证识别与字段核对**）

| 项 | 内容 |
| --- | --- |
| 目标 | 从凭证图片提取关键字段（商家、金额、下单时间、商品名、订单号后四位等），展示识别结果并允许用户核对 |
| 前置条件 | 阶段 2 图片模型能力结论；阶段 4 上传可用 |
| 最小交付物 | 识别服务端函数、字段核对界面（可编辑、可标记「未识别」）、提示「AI 识别结果仅供参考」 |
| 验收条件 | 用**合成样例**凭证测试：每个字段标注来源（识别/用户填写）；识别失败时输入「未识别」而非默认值；至少 5 张不同版式合成样例的实测记录 |
| 证据位置 | `evidence/ai-collaboration/01-凭证识别与字段核对.md`（含迭代链）、录屏、测试记录 |

### 阶段 6 · 事实整理与证据检查（**核心功能 ②：事实时间线**）

| 项 | 内容 |
| --- | --- |
| 目标 | 将字段与用户陈述整理为时间线，并检查证据缺口（如「缺少商家拒绝的截图」） |
| 前置条件 | 阶段 5 字段可用 |
| 最小交付物 | 时间线视图、证据清单、缺口标注、三类来源标记（用户陈述/识别结果/AI 推断） |
| 验收条件 | 每条时间线条目可点开看到来源；AI 推断条目有明确标记；缺口检测在构造的样例上有对错记录 |
| 证据位置 | `evidence/ai-collaboration/02-事实时间线与证据检查.md` |

### 阶段 7 · 法规检索（**核心功能 ③ 的前半**）

| 项 | 内容 |
| --- | --- |
| 目标 | 建立小规模法规语料（含**官方来源 URL、版本、生效状态**），实现本地检索 |
| 前置条件 | 语料来源清单确定；SQLite FTS5 中文检索可行性实测（见技术方案评估） |
| 最小交付物 | 语料目录 + 导入脚本 + 检索接口 + 命中片段与来源展示 |
| 验收条件 | 一组典型中文查询的命中结果人工判读记录（含失败案例）；每条结果可跳转官方来源；**未命中时说「未找到」，不编造** |
| 证据位置 | `evidence/ai-collaboration/03-法规检索与有来源分析材料.md`；检索测试数据集 |

### 阶段 8 · 分析与沟通材料生成（**核心功能 ③ 的后半**）

| 项 | 内容 |
| --- | --- |
| 目标 | 基于前序事实 + 检索到的法规片段，生成初步权益分析与沟通材料草稿 |
| 前置条件 | 阶段 7 检索可用；字段与时间线稳定 |
| 最小交付物 | 分析章节（结论/依据/不确定点）、沟通话术或投诉材料草稿、固定免责声明 |
| 验收条件 | 生成内容里每处法规引用都能对应检索结果中的条目；引用失败时不生成该条；人工抽检并记录「是否出现幻觉引用」 |
| 证据位置 | `evidence/ai-collaboration/03-...`（迭代链最完整的一个） |

### 阶段 9 · 测试与隐私检查

| 项 | 内容 |
| --- | --- |
| 目标 | 补齐关键单元测试与完整闭环端到端测试，执行隐私自查 |
| 前置条件 | 阶段 4—8 功能可用 |
| 最小交付物 | Vitest 用例（字段归一化、来源标记、检索、引用校验）、Playwright 闭环用例、隐私自查清单结果 |
| 验收条件 | 测试真实运行并保留输出；隐私自查逐项打勾；**未通过的用例如实列出** |
| 证据位置 | `tests/`、`docs/` 中的测试结论、`evidence/screenshots/` |

### 阶段 10 · 部署与比赛材料

| 项 | 内容 |
| --- | --- |
| 目标 | 提供可访问演示、完成复现指南计时、Demo 成片、技术 PDF |

| 最小交付物 | 部署地址或本地一键启动脚本、`docs/复现指南.md` 实测版、`demo/final-1080p.mp4`、技术 PDF（≤30 页）、README 定稿 |

| 证据位置 | `evidence/demo/`、`evidence/recordings/`、`docs/比赛材料清单.md` |

## 5. 不做的范围（防止范围膨胀）

- 不做多场景并发开发，先跑通一个场景。
- 不做用户账号体系、支付、社交等非核心功能（除非评审明确要求）。
- 不做 Embedding 优先方案，优先验证 FTS5（见技术方案评估）。
- 不做多模型调度框架，先做最小适配层。
- 不做「自动帮你投诉/起诉」类功能。
