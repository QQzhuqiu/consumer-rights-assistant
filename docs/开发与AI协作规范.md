# 开发与 AI 协作规范

本文件定义「凭证明白」项目中**人与 AI 如何协作、留下什么证据、如何保护隐私**。
适用于后续所有阶段；与本文件冲突的做法以本文件为准，修改需在文末记录变更。

---

## 1. 角色与责任

| 角色 | 责任 |
| --- | --- |
| 用户（人类，项目负责人） | 确认产品方向与场景；提供官方比赛资料；验收每个阶段成果；配置密钥；执行录音/录屏；最终判断证据是否可提交 |
| AI 编程助手 | 按任务边界执行；如实报告失败与阻碍；不虚构结果；整理可核验的记录 |
| 人工审核（用户执行） | 对 AI 产出的代码与文档做复核，确认「不编造法规、不混淆陈述与推断」等红线 |

**AI 自检不能代替人工验收。** 任何标为「通过」的验收结论只能由用户填写。

## 2. AI 是「执行者 + 证据记录者」，不是「作者」

- AI 生成的内容必须能被追溯到某次真实交互（Prompt 记录 ID）。
- 不根据记忆「重构」逐字对话；原始记录未保存就写「待用户导出补充」。
- 不为凑提交数量拆分无意义提交；不为凑 Bug 记录制造 Bug。

## 3. 意图控制与信息分层（产品内同理）

项目对「信息可信度」有硬性要求，开发过程也遵守同一套分层：

| 层级 | 含义 | 示例 |
| --- | --- | --- |
| **用户陈述** | 用户口述的事实 | 「商家说 7 天内可退」 |
| **材料识别结果** | 从凭证图片中识别出的字段 | 「订单金额 ￥299.00（识别置信度低）」 |
| **AI 推断** | 基于规则/法规给出的判断 | 「该情形可能适用七天无理由退货」 |

代码与 UI 中必须能区分这三类来源，无法确认的字段显式标注「未识别 / 待核对」，
不允许用默认值静默填充。文档中也一样：**未核实的内容标注「待验证」**。

## 4. Prompt 与记录规范

### 4.1 每次有实质产出的交互，都应生成一条记录

- 位置：`prompts/<分类>/<阶段号><分类号>-<序号>-<主题>.md`
- 模板：`prompts/交互记录模板.md`
- 分类：`01-项目初始化`、`02-核心功能开发`、`03-Bug修复`、`04-代码审查`

### 4.2 必须填写的内容

记录 ID、实际时间、功能与目标、模型展示名称（**实际模型 ID 不明时标「未验证」**）、
用户原始 Prompt、AI 原始回复或原始导出位置、人工修改意见与后续 Prompt、
实际文件变更与关联 Git 提交、实际 Bug 与修复、实际执行的命令与结果、
人工验收状态、未解决问题与证据路径。

### 4.3 三类材料严格区分

| 类型 | 标识 | 位置 |
| --- | --- | --- |
| 原始导出 | 文件名/目录含 `raw` 或 `原始` | 本地保存，不入库 |
| 脱敏副本 | 文件名含 `-redacted`，文首写脱敏范围 | `prompts/` 可提交 |
| 人工摘要 | 文件名含 `-summary` 或明确标注 | 可提交，不得冒充原文 |

同一份内容只保留一个主副本，其他位置用相对路径引用。

### 4.4 历史不可篡改

已提交的记录只追加。需要更正时在该文件末尾追加「更正说明」（日期、内容、依据），
不覆盖原有段落，不 `git commit --amend` 改写已推送的历史。

## 5. 代码约定

### 5.1 AI 生成代码的约束

| 约束 | 要求 |
| --- | --- |
| 范围 | 只改任务要求的文件；不顺手重构无关模块 |
| 依赖 | 引入新依赖前说明理由、版本、体积与替代方案，经用户同意 |
| 密钥 | 只从服务端环境变量读取；禁止 `NEXT_PUBLIC_` 前缀的密钥；禁止硬编码 |
| 法律信息 | 法规条文、编号、生效日期必须有可核验来源（官方发布页 URL）；**宁可留空也不编造** |
| 不确定性 | 无法确认的字段/结论必须显式标注，不得用默认值掩盖 |
| 免责声明 | 输出页面固定包含「仅供参考，不替代专业法律意见」 |
| 类型 | 若使用 TypeScript，避免 `any` 逃逸；错误分支必须处理 |
| 注释 | 说明「为什么」，不复述代码 |

### 5.2 人工审核机制

1. **AI 提交前自检**：改动清单、命令结果、是否引入依赖、是否触碰密钥。
2. **人工复核点**：
   - 涉及法规/法律表述的内容 **必须**人工核对来源；
   - 涉及个人信息处理路径（上传、存储、删除）的代码 **必须**人工确认；
   - 涉及模型调用的错误处理与费用控制 **必须**人工确认参数。
3. **不通过即回退**，并在 `prompts/04-代码审查/` 留下否决理由。

### 5.3 模型调用（待实现，此处为约束）

- 文本任务与图片任务分开设计；**不支持图片的适配器不实现 vision 方法**，不强行统一接口。
- 不默认所有服务商兼容同一协议；先测后适配，最小适配层放在 API 测试通过之后再设计。
- 每次调用必须有：超时、重试上限、费用/用量记录、错误分类。
- 单一 API 总预算约 20 美元；**单轮费用上限由用户确认后**才可批量调用。

## 6. 隐私与信息安全

| 类别 | 规则 |
| --- | --- |
| 密钥 | 只在 `.env.local`（已忽略）；不进代码、不进截图、不进日志、不进 Prompt 记录 |
| 真实凭证 | 不提交仓库；演示只用合成或脱敏样例 |
| 截图/录屏 | 录制前关闭含密钥终端、含真实凭证页面；导出前抽帧复查 |
| 日志 | 不打印身份标识、订单号、完整请求头 |
| 仓库 | `.gitignore` 覆盖密钥、数据库、`data/` 内容与 `evidence/` 原始媒体 |
| 分享 | 对外材料（README、技术 PDF、Demo）使用合成数据截图 |

## 7. 录屏安排

### 7.1 什么时候必须录

1. **初始化收尾的补充镜头**（本阶段未录制，可在用户验收后补录真实操作过程）。
2. **三个核心功能开发开始前**启动录屏，直到该功能通过人工验收。

> 提醒：录屏开始前先启动录制工具，避免漏掉真实的 Prompt 输入与调试过程；
> 中途出现错误不要停止录制、不要重录「成功版」，因为真实排查过程本身就是证据。

### 7.2 录制内容要求

必须包含（真实发生即可，不要求每个都出现）：

- Prompt 的实际输入过程
- AI 修改代码的过程与 diff
- 人工反馈（否决、纠正、追加要求）
- 实际问题的排查（报错、定位、尝试、最终修复）
- 检查结果（测试、字段核对、检索命中情况）

### 7.3 剪辑与成片

- 最终成片：**1080P、MP4、5—8 分钟，其中至少 2 分钟真实 AI 辅助开发**
  （**已核实**：官方作品要求明确写明「演示视频：5-8分钟(MP4 1080p)，必须包含至少2分钟的
  'AI协同过程复现展示'」）。
- 不要求每个功能录制固定时长；不制造故障、不摆拍。
- 剪辑只做删减与字幕，不改变事实顺序，不拼接「像连续发生」的假流程。

> **官方替代条款**：AI 对话历史若工具不支持导出，**可用截图或录屏代替**。
> 因此录屏不仅服务于 Demo，它本身就是「Prompt 历史快照」的合规证据形式。
> 这意味着：**录屏是硬性得分项，不是可选装饰**。

### 7.4 录制前检查清单（每次）

- [ ] 关闭含 API Key 的终端与 `.env` 文件窗口
- [ ] 关闭真实消费凭证页面，切换到合成样例
- [ ] 通知栏无私人消息
- [ ] 浏览器无自动填充的个人信息
- [ ] 录制结束后抽帧复查，发现敏感信息立即删除该段

### 7.5 工具候选（不自动安装或控制）

| 类型 | 候选 | 备注 |
| --- | --- | --- |
| 屏幕录制 | OBS Studio、Windows 自带 Xbox Game Bar | 需用户自行安装/启用；本项目不代为安装或操作 |
| 剪辑 | 剪映、DaVinci Resolve、ffmpeg | 1080P MP4 输出 |
| 截图 | Windows 截图工具、Snipaste | 导出前脱敏 |

### 7.6 素材管理

- 大体积素材**本地保存**，`.gitignore` 已忽略视频格式，不进 Git。
- 在 `evidence/recordings/README.md`、`evidence/demo/README.md` 的登记表记录
  备份位置、时间与抽帧复查结果。
- 成片通过比赛平台或网盘提交，仓库只放分镜与镜头清单。

## 8. 文档写作规范

- 结论必须带状态标记：✅ 已验证 / ⚠️ 待验证 / ❌ 未完成 / 未发生。
- 计划与成果分开写，**计划不能写成已完成**。
- 引用法规、比赛规则、官方文档时给出可点击来源；无法核实的写「待用户提供官方资料复核」。
- 不使用「已完美实现」「全面覆盖」等无法验证的表述。
