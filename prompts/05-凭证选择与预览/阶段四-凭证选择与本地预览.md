## 1. 本阶段任务（脱敏）

在现有首页中增加一个**纯本地**凭证预览区域，不涉及任何服务端交互：

- 单文件选择，`accept` 精确限定为 `image/jpeg,image/png,image/webp,application/pdf`；
- 单文件上限 10 MiB（代码中为 `10 * 1024 * 1024`）；
- 类型不支持或超出上限时显示错误，且**不显示预览**；
- 图片使用浏览器本地对象 URL 预览；
- PDF 使用原生 `<iframe>` 预览；无法内嵌时显示明确的文本占位；
- 提供「移除文件」与「替换文件」两个真实按钮；
- 明确告知：文件仅在浏览器本地预览，不会上传服务器。

## 2. 方案选择

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 组件拆分 | 新增独立客户端组件 `src/app/evidence-preview.tsx` | `page.tsx` 已含卡片微交互逻辑，混入预览功能会使单文件职责过多 |
| `use client` | 该组件独立声明 | 需要 `useState` / `useRef` / `useEffect` 管理选择状态与对象 URL |
| PDF 预览 | 浏览器原生 iframe | 不引入 pdf.js 等第三方依赖 |
| 依赖 | **无新增** | 对象 URL、`<input type="file">`、`<iframe>` 均为浏览器内置能力 |

## 3. 功能边界

**能力范围**：单文件；类型限 JPEG / PNG / WebP / PDF；最大 10 MiB；仅在浏览器本地预览。

**明确不做**：不上传文件、不发送任何网络请求、不调用模型 API、不读取环境变量；
不做 OCR 与 AI 识别、不做字段提取、时间线分析、法规检索或材料生成；
不使用数据库、不写入 `localStorage` / `sessionStorage` 或任何浏览器持久化；
不支持多文件、不支持 HEIC；不给 4 个静态占位卡片添加点击行为。

页面刷新或关闭后状态自然清空。

## 4. 校验逻辑

按顺序执行，任一不通过即中止并显示错误：

1. `file.type === ''` → 无法确定类型，按不支持处理（部分系统不提供 MIME 信息）；
2. `!ALLOWED_MIME_TYPES.has(file.type)` → 不支持的类型，错误文案回显实际 MIME；
3. `file.size > 10 * 1024 * 1024` → 超出上限，错误文案回显实际大小。

错误信息通过 `role="alert"` 呈现，并通过 `aria-describedby` 关联到文件选择控件。

## 5. 对象 URL 生命周期

单一所有权：任意时刻最多一个对象 URL 存活，由组件内的 ref 持有。

| 时机 | 处理 |
| --- | --- |
| 校验通过后 | 先释放旧 URL（替换场景），再 `URL.createObjectURL(file)` 并存入 ref |
| 校验失败时 | 释放可能存在的旧 URL，清空预览，仅显示错误 |
| 移除 | 释放 URL，清空状态，重置原生 input 值 |
| 替换 | 重置 input 值并重新打开选择框；选中后走「先释放、再创建」路径 |
| 组件卸载 | `useEffect` 清理函数释放仍存活的 URL |

以上为代码内部实现说明，**不属于浏览器验收项**。
