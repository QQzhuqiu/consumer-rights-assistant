## 1. 本阶段目标

在阶段 4.1 的本地凭证预览之后，增加一个**由固定样例驱动的识别结果核对区域**，用于验证：

- 字段数据结构是否合理；
- 识别结果如何展示（含置信度、来源、备注）；
- 用户如何逐字段确认；
- 用户如何修改字段；
- 未识别字段与低置信度字段如何提示；
- 刷新后编辑与确认状态是否清除；
- 窄屏布局是否可用。

## 2. 为什么用固定样例而不是真实模型

本阶段**刻意不接入真实视觉模型**，原因：

1. **先验证数据结构与交互**。字段结构、确认语义、编辑与确认的分离规则，
   如果在接入模型之后才暴露问题，改动成本会高得多；
2. **避免把「模型能力」和「界面设计」混在一起排查**。当前模型视觉能力本身仍
   未完成验证（见阶段二记录），此时把两者耦合会让问题定位困难；
3. **避免真实凭证进入处理链路**。在隐私边界、脱敏规则、用户确认流程尚未成型前，
   不应让真实凭证数据流经识别流程；
4. **可重复**。固定样例每次渲染完全一致，便于逐项核对界面行为。

因此本阶段的样例数据**只用于验证 UI 和状态管理**，界面上必须明确标注它
不是真实识别结果。

## 3. 允许与禁止的范围

### 本阶段实现

- TypeScript 字段类型；
- 固定样例数据；
- 本地识别结果展示；
- 单字段确认 / 撤销确认；
- 单字段编辑保存与取消；
- 标记字段为未知；
- 全部确认；
- 重置为样例；
- 刷新后恢复初始样例；
- 窄屏布局；
- 必要的可访问性文本与控件。

### 本阶段不实现

真实视觉模型；任何模型 API 调用；图片上传；服务端 API 或 API 路由；
OCR；数据库；浏览器持久化（`localStorage` / `sessionStorage` / IndexedDB）；
多文件识别；重新识别；文件导出或下载；事实时间线；证据完整性分析；法规检索；
法律分析；沟通材料生成；账号系统；云存储；队列或后台任务；真实消费凭证处理。

## 4. 字段结构

只支持 5 个字段，不扩展其他字段：

| key | 中文标签 |
| --- | --- |
| `merchantName` | 商家名称 |
| `itemName` | 商品/服务名称 |
| `amount` | 金额 |
| `transactionDate` | 交易日期 |
| `orderId` | 订单号 |

类型定义位于 `src/types/extraction.ts`：

```ts
type FieldConfidence = 'high' | 'medium' | 'low' | 'unknown';
type FieldSource = 'fixture' | 'model' | 'user' | 'unconfirmed';
type ExtractionStatus = 'success' | 'partial' | 'failed';

type ExtractedField = {
  key: ExtractionFieldKey;
  label: string;
  value: string | null;
  confidence: FieldConfidence;
  source: FieldSource;
  note?: string;
  confirmed: boolean;
};

type ExtractionResult = {
  fields: ExtractedField[];
  globalNote?: string;
  status: ExtractionStatus;
};
```

约束：

- 样例数据的 `source` 全部为 `'fixture'`；
- 本阶段**不产生** `source: 'model'`，该值仅为类型预留；
- 所有字段初始 `confirmed: false`；
- `value: null` 表示当前没有可确认的值；
- `confidence: 'unknown'` 表示无法判断或未识别；
- 类型文件只放类型与纯常量映射，不调用浏览器 API、不发起网络请求、无副作用。

## 5. 样例数据说明

固定样例位于 `src/lib/extraction-fixture.ts`，覆盖四种置信度，并包含两个空值字段：

| 字段 | 置信度 | 值 |
| --- | --- | --- |
| 商家名称 | 高置信度 | 有值（合成） |
| 商品/服务名称 | 中置信度 | 有值（合成） |
| 金额 | 低置信度 | 有值（合成），附「缺少货币符号」备注 |
| 交易日期 | 无法判断/未识别 | `null` |
| 订单号 | 无法判断/未识别 | `null` |

样例中的商户名、商品名、金额均为**合成内容**，不含真实商户、真实订单号或个人信息。

`createInitialFields()` 每次返回全新副本，因此界面上的编辑不会污染共享的样例常量。

## 6. 用户核对行为

| 操作 | value | confidence | source | confirmed |
| --- | --- | --- | --- | --- |
| 初始（样例） | 样例值 / `null` | 四种覆盖 | `'fixture'` | `false` |
| 确认 | 不变 | 不变 | 不变 | → `true` |
| 撤销确认 | 不变 | 不变 | 不变 | → `false` |
| 编辑并保存（内容已变） | 用户输入 | 保持原值 | → `'user'` | → `false` |
| 编辑并保存（内容未变） | 不变 | 不变 | 不变 | 不变 |
| 编辑留空并保存（原本有值） | → `null` | → `'unknown'` | → `'user'` | → `false` |
| 取消编辑 | 恢复编辑前值 | 不变 | 不变 | 不变 |
| 标记为未知 | → `null` | → `'unknown'` | → `'user'` | → `false` |
| 恢复样例状态 | 恢复 fixture 原值或原始 `null` | 恢复 fixture 值 | → `'fixture'` | → `false` |
| 全部确认 | 不变 | 不变 | 不变 | 全部 → `true` |
| 重置为样例 | 样例原值 | 样例原值 | → `'fixture'` | 全部 → `false` |

关于「编辑并保存（内容未变）」的判定规则：

- 比较 `field.value?.trim()` 与 `draftValue.trim()`；
- `null` 与空字符串都视为空值；
- 首尾空格不算实质变化；
- 内容未变化时**不调用字段更新**，`value`、`confidence`、`source`、`confirmed` 四项状态均不改变，
  只退出编辑态并清空草稿；
- 内容确有变化时才把 `source` 改为 `'user'`，并把 `confirmed` 设为 `false`；
- Enter 保存和「保存修改」按钮**共用同一个保存逻辑**。

### 编辑与确认严格分离

保存编辑时，若内容实际变化，`confirmed` 归零，用户必须再单独执行确认。
若内容未实际变化（包括仅增删首尾空格、原本 `null` 保持空值），
保存只退出编辑态，不改动 `value`、`confidence`、`source` 或 `confirmed`。
清空输入框后保存**不会**被自动视为已确认。

### 空值字段的确认语义

对 `value: null` 的字段，确认按钮文案为「确认「字段名」未知」，
明确表达用户确认的是**该字段确实未知**，而不是确认了某个值。

## 7. 刷新后的行为

本阶段不使用任何持久化，因此：

- 刷新页面后，字段编辑内容消失；
- 已确认状态消失；
- 页面恢复为**初始固定样例**；
- 页面**不是**回到空白的文件选择状态；
- 未写入 `localStorage`、`sessionStorage`、IndexedDB 或任何其他存储。

## 10. 后续交互修正记录

在首次实现之后，根据用户在浏览器中的实际反馈，对本阶段界面做了以下修正，
**这些内容均已由用户在本机浏览器验收通过**：

1. **原本未知字段也支持恢复样例状态**：此前只有原本有值的字段能恢复；
   现在原本 `value: null` 的字段同样提供「恢复样例状态」，恢复为 fixture 的初始未知状态
   （`value: null` + 原始置信度与备注 + `source: 'fixture'`），**不伪造样例值**；
2. **编辑输入框支持 Enter 保存、Escape 取消**：Enter 只保存编辑，不等于「确认该字段」；
   带 Shift/Ctrl/Meta/Alt 的 Enter 与输入法组合状态（`isComposing` / `keyCode === 229`）不拦截；
3. **确认后焦点留在当前字段**：此前会自动跳到下一个未确认字段，现已改为停留在本字段
   （跟随变为「撤销确认」按钮），前进/后退交给用户自己用 Tab / Shift+Tab 决定；
4. **增加键盘操作提示**：在核对区标题下方增加一行辅助说明
   「Tab / Shift+Tab 前后移动；Enter 执行按钮；编辑时 Enter 保存、Escape 取消」；
5. **优化按钮视觉反馈**：核对区次要按钮改为明确的灰底与边框（不再显得透明），
   统一过渡时长与缓动，收紧 hover 缩放、简化阴影、缩短按下反馈，
   并保持 focus-visible 轮廓、disabled 无悬停反馈、`prefers-reduced-motion` 下关闭动画；
6. **无修改直接保存时保持原字段状态**：打开编辑但不改内容直接保存（含仅增删首尾空格、
   原本 `null` 保持空值）时，不再误把 `source` 改为 `'user'`、不再误显示
   「模型置信度：不适用（用户填写）」或「用户标记为未知」，四项字段状态全部保持原状。
