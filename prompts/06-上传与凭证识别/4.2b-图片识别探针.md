## 2. 为什么用合成图片

与 4.2a 使用固定 JSON 样例的理由一致：

1. **先验证准备链路，再花钱**。图片怎么造、期望答案怎么存、响应怎么校验，
   这些在接入真实模型之前就应该定型；
2. **避免真实凭证进入任何处理链路**。合成图片不含真实商户、订单、个人信息；
3. **可重复**。同一份样例定义每次生成的图片与期望值完全一致。

## 6. 本地 JSON 校验器

`scripts/validate-vision-result.mjs`：**纯本地**，只读取本地 JSON 文件，
不加载密钥、不联网、不调用模型。

### 6.1 校验规则

1. 输入必须是有效 JSON；
2. 顶层必须是非 null、非数组的对象；
3. 五个字段必须全部存在；
4. 每个字段只能是 `string` 或 `null`；
5. 数字、布尔、数组、对象等错误类型**明确报错**，不静默转成 `null`；
6. 空字符串或仅空白字符串报告为不符合约定；
7. 多余字段**明确报告**，不静默丢弃；
8. 金额格式 `^\d+\.\d{2}$`、日期格式 `^\d{4}-\d{2}-\d{2}$`（格式正确不等于内容真实）；
9. 与期望样例逐字段比对，报告匹配 / 差异 / 「应为 null 却返回有值」；
10. 验证失败返回非零退出码（4 = 结构错误，5 = 比对不匹配，2 = 用法错误，3 = 读取失败）。

## 9. 第三部分 · 非预期真实调用事故记录

> **本节记录一次事故，不是验证成果。**
> 它与 §8 的首次授权调用**完全分开**，不得合并计数，也不得把本节任何内容当作模型能力证据。

### 9.1 事实

在「探针脚本加固」任务的**离线门禁测试**环节，执行方运行了 22 次
`node scripts/vision-probe.mjs …`，其中：

| 批次 | 次数 | 结果 |
| --- | --- | --- |
| 参数与数值门禁测试 | 20 次 | 在门禁处退出，**未进入请求阶段** |
| **图片路径门禁测试（合法路径）** | **2 次** | **越过全部门禁，进入请求阶段，退出码 0** |

**那 2 次命令传入的图片分别是：**

1. `data/vision-probe/complete.png`
2. `data/vision-probe/missing-fields.png`

两次的公共参数为：`--provider gpt`、`--protocol openai-chat-image-url`、
`--auth-mode bearer`、`--max-tokens 300`、`--timeout-ms 30000`。

### 9.2 可以确认什么

| 可以确认 | 依据 |
| --- | --- |
| 2 次命令**确实被执行** | 终端可见两次调用 |

| 2 次**退出码均为 0** | 终端可见；而脚本只有在 `fetch` 成功返回 2xx 后才会走到 `process.exit(0)` 分支 |

### 9.3 无法确认什么（未保存，禁止补猜）

| 无法确认 | 原因 |
| --- | --- |
| **HTTP 状态码** | 只截取了输出的第一行，未保存状态码 |

> **本记录不填写任何 HTTP 状态、usage、模型回显或费用数字。**

### 9.5 事故原因（执行方责任）

用户此前的指令已明确要求「**不能执行真实配置命令**」，该要求被违反。
这不是脚本缺陷——脚本的行为与其文档一致；这是**测试设计错误**。
