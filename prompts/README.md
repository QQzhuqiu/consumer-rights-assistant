# prompts —— AI Prompt 与协作记录（可提交部分）

本目录存放**经过检查、可以公开的** Prompt 与 AI 回复文本，是「Prompt 历史」证据的主副本。

## 三类材料必须分清

| 类型 | 位置 | 是否提交 |
| --- | --- | --- |
| 原始记录（工具导出的完整对话、含完整上下文） | 本地另存（例如 `evidence/**/raw/` 或项目外），文件名含 `raw` / `原始` | ❌ 不提交 |
| 脱敏副本 | 本目录下的 `.md` 记录文件，文首注明「脱敏范围」 | ✅ 提交 |
| 人工摘要 | 本目录或用例索引中的人工评审意见 | ✅ 提交，须标注为摘要 |

**脱敏副本不是原始记录。** 记录文件里不得声称自己「逐字完整」，除非确实是逐字导出。

## 目录结构

```
prompts/
  README.md              ← 本文件
  交互记录模板.md          ← 新记录从这里复制
  01-项目初始化/           ← 阶段一：环境检查、目录与文档、Git 初始化
  02-核心功能开发/         ← 核心功能 ① 凭证识别 ② 时间线 ③ 法规检索
  03-Bug修复/             ← 真实发生的 Bug 与修复过程
  04-代码审查/            ← 审查意见、重构、约束检查
```

## 命名约定

```
<阶段号><分类号>-<序号>-<简短主题>.md
例：0101-01-环境检查与目录初始化.md
    0201-03-凭证字段核对规则迭代.md
```

序号在分类内连续递增。**不要**用「最终版」「最新」之类的命名，
历史记录只追加不覆盖；需要更正时在文末追加「更正说明」。

## 记录的真实性红线

1. 没有发生的环节写「未发生」，不确定的写「待补充」，不填空泛的套话。
2. 不根据记忆「重构」逐字 Prompt；原始文本缺失时写「原始文本待用户导出补充」。
3. 不制造 Bug、不编造测试通过、不虚构模型 ID 或耗时。
4. Agent 自检 ≠ 人工验收。人工验收状态默认为「待验收」。
5. 不写入 API Key、访问令牌、真实个人信息、真实消费凭证内容。

## 与 evidence 的关系

每条记录都有一个**记录 ID**，`evidence/ai-collaboration/` 的索引文件用这个 ID
把 Prompt、Git 提交、截图、录屏、测试串起来。两边不重复写正文。
